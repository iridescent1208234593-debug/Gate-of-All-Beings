## 视觉方向与已有规则

- 品牌基调是罗小黑世界观下的宣纸、墨色、松绿与描金；视觉应轻、清楚、有呼吸感，避免通用 SaaS 仪表盘风格、无目的渐变和过量玻璃效果。
- 先复用现有 `--qc-*` tokens、`qc-*` 组件、共享导航和游戏 HUD。不要在页面里散落硬编码颜色、字号、间距或圆角。
- 只有当现有组件确实无法表达需要时才新增通用组件；同步更新设计系统说明、演示页及对应 README，并说明消费者。
- 全站导航只有一条。页面操作应使用导航插槽或现有控件组，不要另加重叠的 `position: fixed` 角落控件。
- 开场、语言、声音、选服、账户和辅助控件在窄屏仍须可见、可点且不重叠。新增浮层先查已有控件位置和挂载生命周期。
- 加载、空态、错误、禁用、键盘焦点与减少动态效果都属于组件视觉的一部分；出错时应给出可理解的原因和可执行的恢复入口。
- 尊重各游戏自身的美术和交互身份；统一基础交互和排版，不要把所有玩法抹成同一张模板。

## 本轮工作目标

1. 选取真实访问频率高、能被多个页面复用的组件作为优先项，例如全局导航、按钮/表单、卡片、弹窗、加载与空错误状态。
2. 检查桌面与窄屏的层级、对齐、可读性、触控区域、焦点状态及控件冲突；找出重复实现后，尽可能复用或收敛到共享层。
3. 做一组可见且范围受控的实际改进，并应用到至少一个真实消费者，确保组件不是只在展示页里好看。
4. 在相关设计系统文档和 README 记录新增/调整的组件契约、布局原因与使用方式，防止同类问题再次出现。
5. 汇报本轮改动文件、覆盖页面、验证方式、尚未处理的问题及是否需要后续分批推进。

若检查后发现整个站群的 UI 任务过大，优先完成一个跨页面共享组件改进和一个代表性页面落地；将其余事项按影响排序列出，继续工作前不需要等待用户确认。
