## 结构

| 层 | 位置 | 说明 |

| 世界规则（纯函数） | `server/app/src/cards/src/world/rules.ts` | `commitResult`、`nightResult`、`sealResult`、`canStartExpedition`、`summarize` 等；全部按游戏日推进，不读现实时钟 |

| 存档 | `world/store.ts` | 统一存档 `mode:world` 一条记录；资源与角色进度走共享账本。一次提交 = 一次 `commitMode`（快照 + 资源增量 + 角色进度 + 回执 ID），原子且可重试 |

## 见闻（JournalEntry）

每条见闻来自一个 `ActivityResult`：`id`（稳定，用于去重）、`activity`、`outcome`、`place`、`companions`、结构化 `changes`、`note`、`encounter`。`Change` 类型：`resource`（`settled` 表示别处已入账，只记录）、`bond`、`wound`、`fall`、`recover`、`seal`、`card`、`meet`、`place`、`world-event`。重伤带回的牌组走 `result.carry` 写进照料状态，不进见闻。

回到手记时，未读见闻合并成摘要直接显示在首页：资源增减、同行者新伤/痊愈、默契增量、图鉴新卡、地点变化。点「收好这些见闻」或开始下一个玩法即标记已读。

## 时间

一天分清晨/傍晚。占用白天的玩法（出行、重生之门、留在会馆）只能在清晨开始，结束后到傍晚；「歇下」过夜到次日清晨并结算照料：种植草药 +2、修习默契 +3、休息灵质 +4；重伤者「林间休息」2 夜并用 2 草药痊愈；全员陨落后从最后一位倒下算 2 夜一起恢复。常量都在 `RULES`。

**冲突提醒**：旧 `#adventure` 仍用「全员陨落 5 小时复活」的现实时间规则，两边读写同一份角色伤亡计数。手记成为主入口时需要退役旧规则（`core/meta.ts` 的 `reviveIfDue` / `allDeadAt` 与 `storage.ts` 的 `reviveAt` 换算），否则旧页面的计时可能提前复活同行者。

## 新玩法如何接入

1. 写一个适配器：开始时从 `WorldState` + 出行配置建立该玩法的局内状态（存进 `ActivitySession.state`），结束时返回 `ActivityResult`。
2. 结果交给 `commitResult` → `saveWorld`，不要自己改资源余额或角色进度。
3. 资源已由该玩法在账本里用 `transact` 结算的，`changes` 里标 `settled: true`，并带上 `receipt`。

重生之门换到入世历练引擎（见 README「后续战斗引擎收敛」）完成后，应改成第 1 种方式：作为 `activity: 'rebirth-gate'` 的正式适配器，删除现在基于账本回执的 `rebirthResults` 过渡写法。
