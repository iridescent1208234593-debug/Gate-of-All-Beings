# 西木会馆共创身份与 LAB 账户联动：候选上线/回滚清单

**这是隔离候选，没有在香港或现有 LAB 上发布。** 当前生产版本与仓库有差异，不能直接用本分支覆盖线上旧布局或把测试数据库复制到香港；应先在不接触用户记录的生产版本副本比对补丁、部署路由和 SQLite 表版本。

## 数据和边界

- 会馆账户及会话仍由原有服务管理。会员绑定用原有 `(kind,uid)`。`creator_memberships` 记录驻馆、客席及多组多职能；`creator_profiles` 记录用户公开授权；`creator_contributions` 另存贡献，可关联账户也可作为经许可的独立鸣谢；`creator_audit` 写入操作人、对象、时间和变更。所有表为增量创建，旧用户、密码、OC 和权限字段不重写。
- 只在原 `/connections.html` 追加档案，保留旧鸣谢、联系、反馈和维护支持。无自动从旧鸣谢名单导入账号、署名、头像和外部作品；已在原页面公开的历史鸣谢不做批量迁移，新增或转录前核证许可。
- 管理员负责身份及贡献审核；成员可以独立撤回公开档案、头像、链接和贡献。重要成员资料的版本变化会收回对新内容的发布授权；新/修改后批准的贡献须再次确认。退出共创组不会删贡献；仅继续展示仍经授权的历史署名。会馆账号删除会撤回公开授权及成员身份，保留内部历史而不因同一 USSO 重新登记再公开；上线前确定内部保存期及撤回流程。
- 身份授权在系统浏览器确认，不向游戏收会馆密码，不向 LAB 提供真实账户 ID、会话 cookie、邮箱或完整数据库。两个服务只共享专用认证凭证（环境独立，服务端持有）、会馆签发的专用 `sub` 和短效 grant。详情见 [LAB_ACCOUNT_BROKER.md](LAB_ACCOUNT_BROKER.md)，该流程不是通用 OIDC 服务。会馆注册不等于 LAB 准入；默认不授予，不从身份批量推导。
- 旧游戏领域的身份、OC 与世界存档不做昵称匹配、不合并两个既有存档。对已明确授权的一人一码，在用户证明自己可访问旧 LAB 且明确选择绑定后，只复用原玩家归属。无法确认归属或多人用码时暂不迁移。保留未绑定旧码的独立回退。

## 上线前，不含正式执行

1. 在隔离与目标版本一致的两套测试服务装载，检查会馆登录、目录读写、旧码、授权领取与退出、OC/聊天/小游戏/虹之间。核对经隧道 root/audience、TLS、服务器权限及 credential 不进入浏览器和打包客户端。手机真机和正式线上隧道需分开验收。
2. 确定准入审批者和首批少数测试人员名单；待成员本人确认公开字段和作品许可后再填名录。客服明确怎么回收测试资格、撤回展示和处理存档归属争议。不默认授予驻馆或客席。
3. 原条款/隐私说明对 LAB 有独立范围约定，不直接以技术改动替代告知。正式开启前应审定 LAB 专用告知：会馆发出的专用身份、授权与撤销；LAB 保存的玩家资料和游戏内容；链接展示授权及撤回；实际存放地和联系人。仍不迁移香港全量账户库，赞赏不换站内权益。
4. 对生产版先做一次可恢复、可验证的必要 SQLite 恢复点（使用在线备份 API 或停写后的受控复制，含完整性检查及读回演练），不重复备份。记录当前版本/功能开关、迁移状态与已放行人员。**正式生产迁移、权限切换和发布需先给负责人变更摘要与回滚方案，并等明确确认。**

## 启停和回滚顺序

- 共创独立上线开关 `IRIDESCENTLY_CREATORS_ENABLED` 默认关闭；关闭后恢复旧页面内容，增量表保留，不清库。
- 会馆认证发行站需显式配置 `IRIDESCENTLY_LAB_ACCOUNT_BROKER_ORIGIN`（已登记的精确 HTTPS 会馆来源）和服务端密钥 `IRIDESCENTLY_LAB_ACCOUNT_BROKER_BEARER`。无有效配置时新认证不启用。正式服务的密钥由部署环境安全注入，不进 Git、附件或客户端。
- 先让兼容服务正常运行，再小批开启新会馆账户准入。回滚先关 LAB 新登录和迁移，保证未受影响的旧入口；会馆端停止新授权并使相关租约过期，必要时撤销授权。已绑定旧码的恢复需要按授权策略审核，不能把关闭新会馆认证与无条件重新开放旧身份混为一谈。
- 回滚优先旧代码/功能开关，保留新增表和审核记录；不在新旧程序混跑时还原整个数据库，避免丢失期间有效进度。如果确认需要数据库恢复，停写、执行恢复点演练步骤，并核对停机后的新增记录处置。
