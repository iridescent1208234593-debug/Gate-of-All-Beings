# AI 单次任务模板

复制下面模板给 Claude / Codex / Copilot 等工具。项目背景不要重复粘贴，先让 AI 阅读仓库规则。

```text
先阅读并遵守：
- AGENTS.md
- docs/development/AI_DEVELOPMENT.md
- docs/development/GLOSSARY.md
- docs/development/NAMING_AND_CONTRACTS.md
- 与本任务相关的架构/API/数据文档
- .github/instructions/ 中匹配改动路径的规则

任务目标：
<一句话说明最终要实现什么>

允许修改：
- <路径/模块>
- <路径/模块>

禁止修改：
- 生产环境、Cloudflare、DNS、Tunnel、OAuth、真实数据库/上传
- <本任务特别禁止的模块或契约>

必须保持：
- <兼容性/已有行为>
- <数据边界/权限边界>

开始编码前：
1. 搜索现有实现、共享类型、字段、API、Schema 与测试；
2. 列出准备复用的 canonical 实现；
3. 若准备新增核心术语/字段/API/环境变量，先说明为什么现有概念不能复用；
4. 不做与任务无关的重构或顺手重命名。

验收条件：
1. <可验证条件>
2. <可验证条件>
3. <可验证条件>

验证：
- <具体测试命令>
- <具体构建命令>

交付时报告：
- 改动文件；
- 行为变化；
- 公共契约变化；
- 新增术语/字段/API/环境变量；
- 兼容/迁移方式；
- 实际测试结果；
- 未验证项和剩余风险。
```

## 简短任务版

小修复也至少使用以下信息：

```text
先读 AGENTS.md 与 docs/development/AI_DEVELOPMENT.md，并检查相关源码和测试。

目标：<目标>
范围：<允许路径>
禁止：不要改 <边界>
保持：<兼容要求>
验收：<结果>
测试：<命令>
```

不要使用“你自己决定最优架构”“顺便把相关代码全部优化一下”之类的开放授权，除非任务本身就是明确批准的架构重构。
