# 同人画廊历史与排序

## 公开列表

- `GET /api/fan/list` 的 `sort` 可选 `likes`（默认）或 `newest`。响应回传 `sort`，卡片包含 `like_count` 和 `published_at`。不改变立绘／纯文字／AI 分区，及搜索、类型、分页、可见性规则；未审核或已隐藏的记录不进入公开查询。Toy 档案维持现有规则。
- `likes` 仅按正票数量倒序，不以喜欢或踩加减；平手按公开时间与画廊卡片 ID。 `newest` 按公开时间与 ID 倒序。
- `fan_characters.published_at` 只在新卡已批准且公开，或旧卡重新进入「已批准且公开」时写入；普通编辑、无状态变化的公开按钮或重复审核不重置。历史未记录公开时间的卡优先读可辨认的成功审核时间，其次创建时间，均无则返回 `null`；回退值是排序线索，不是对实际历史公开时间的认定。

## 管理员历史

- 普通同人设表按画廊卡片 ID 保留至多三份已通过且公开的内容稿，不复制点赞或收藏、不替换活跃卡片。只留站内附件安全引用，不复制原图；超长文字会按字段标明节略。同内容重复公开不生成新稿。上线前存在的公开稿只可在后续改动前即时观察，不补造历史。
- `fan_history_events` 单独追加审核通过／退回、提交、公开／撤回、内容修改及关联设定移除，保存操作者、时间和状态。仅稿件表执行滚动保留；操作记录不随稿件移除。配色海报的独立变更流程不纳入设表历史。旧行上的最后审核字段并不是全量操作历史。
- `GET /api/admin/fan/history?id=<id>[&before=<next_before>]` 返回最新稿件和最多 50 条操作记录；`POST /api/admin/fan/history/find` 接收 `{ "name": "完整标题" }`，精确查找并返回脱敏展示名与卡片 ID。两者均使用原会馆管理员鉴权与禁止缓存策略；查找还检查同源请求。不会返回账户登录名、原始账户标识、邮箱、会话或票明细。已验证昵称可用于区分操作人，稳定操作标签可处理重名。不存在自动恢复或重新发布历史的接口。

### 管理员送回复审

- 同一历史响应以 `reopen: null` 表示当前无资格；非配色海报设表仅当 `is_public=1` 且 `review_status='rejected'` 才包含 `{review_version, rejection_reason}`。该版本绑定当前卡片与退回状态，不能用于普通审核。
- `POST /api/admin/fan/history/reopen` 接收 `{id, review_version, reason}`，要求站点管理员和相同站点来源。理由去空白后为 2–200 字。成功返回 `{ok:true, id, review_status:"pending"}`；版本变化、失去资格或重复提交返回 409。动作不改 ID、内容、作者、公开申请或票数，不等于审核通过。
- 待审变更与 `moderation_reopen` 审计记录同一事务提交。新增私有 `fan_history_events.prior_review` 保存退回时间、审核者和理由，不经 API 返回。启动会自动添加可空列；不改写现有历史行。正式切换前仍需验证 SQLite 恢复点。

### 作者实质修改后复审

- 已申请公开的关联同人设表发生实质修改后，原卡进入 `pending`，不因作者同时是审核员、长老或管理员而自动通过。不变的保存不触发复审。保留卡片 ID、票数和公开申请；公开接口不返回待审稿，也不替换为历史稿。已撤回仍保持撤回，不批量重审存量，不改首次投稿、配色海报或其他独立分享的规则。
- 单张保存、批量保存及配色调整关联 OC 的保存响应新增布尔字段 `fan_review_pending`：仅当本次实际修订让仍申请公开的关联卡片送回复审时为真，即使修改前已处于待审；无改动、未关联或已撤回不据此提示已送审。该字段不替代审核队列状态，也不会让非公开记录公开。
- `GET /api/fan/review/queue` 每条记录均包含布尔字段 `needs_independent_review` 与 `can_approve`。前者表示需由作者以外的审核员复审，后者针对当前请求者：仅作者本人遇到自己的此类修订时为假。提交时服务端重新校验作者和审核版本，作者本人通过或退回该修订均返回 HTTP 403，机器码 `fan_revision_self_review_forbidden`。管理员送回复审仍不是批准。
- 作者修订送审的持久事件 `owner_revision_submitted` 与当前稿的变更同一事务写入；复用已有历史存储，不新增表或列；标记持续到其他审核员通过。评审中的新版本再次变更后，旧审核版本失效。

## 上线检查与回退

变更随会馆启动创建新增表、索引、公开时间列和触发器，不批量改写旧卡或旧票。先在已验证的隔离版复跑同人历史与排序，核验普通访客、作者与管理员权限，以及同一张卡重新公开后 ID 和点赞不变。使用已验证可恢复的 SQLite 备份；必要时回退旧代码，保留新增表和期间有效的记录，不用旧整库覆盖后来写入。若旧代码继续使用同一数据库，新增时间触发器会保留，须在隔离回退演练中核验预期。不得据此执行线上操作。
