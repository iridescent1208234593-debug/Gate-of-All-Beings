# Git 分支策略

生效于 2026-10-26。取代 2026-10-25 的建议稿（那份的事实已过时：`zszm-batch-20261021` 等分支已并入 canonical 线）。

## 长期线

| 线 | 作用 | 规则 |
| --- | --- | --- |
| **trunk**（当前名为 `batch/7-canonical-structure`） | 唯一的集成与发布来源。Batch 6 存储分离、10-24 安全加固、apps/services/packages/tools/infra 布局都在这里。 | 只通过 PR 合入；PR 必须通过 `regression` 与 `merge-gate`（与最新 trunk 合并后的检查）；不强推、不改写历史。 |
| `master` | GitHub 默认分支，目前完全包含在 trunk 之内（落后、无独有提交）。 | 负责人决定后快进到 trunk 并成为 trunk 的正式名称；在此之前不在 `master` 上开新工作。 |

香港生产在迁移到本布局之前运行旧布局。线上热修复如果只能基于旧布局，必须同时：在变更记录里写明对应的线上版本与文件；在一周内移植进 trunk（按本布局与三根域规则）。移植合并之前，热修复分支保持原样，不删除。

## 短期分支

- 从最新 trunk 创建，名字说明内容：`feat/…`、`fix/…`、`chore/…`、`docs/…`、`perf/…`、`infra/…`。不用分支名推断内容；比对内容决定去留。
- 一个分支一个 PR；合并后删除分支。本机 worktree 放在工作区 `worktrees/<分支名>`（见 [工程工作区](../workspace.md)），分支合并后随之退役。
- 协作者的分支在评审之前不合并、不删除、不改写。

## 归档

- 要删除一个仍有独有提交、或承载过线上谱系的分支：先推送注释 tag `archive/<分支名>`（指向分支当前 tip，说明原因与 trunk 提交），确认远端 tag 与分支 tip 一致，再用 `--force-with-lease=<分支>:<tip>` 删除远端分支。完全被 trunk 包含的分支同样先打 tag，保留名字与提交的对应。
- 不能公开推送的历史（未审查的早期提交、dangling commit、未提交工作的快照）固定在本机 `refs/archive/*`，并随仓库 bundle 一起保存在换盘备份里；它们不推送。
- 历史状态用 tag 和归档 ref 表达，不用分支表达。

## 需要负责人批准的操作

切换 GitHub 默认分支、修改分支保护、删除协作者分支、任何强推或历史改写。删除已证明被 trunk 吸收并已打归档 tag 的分支，按上面的归档规则执行即可。
