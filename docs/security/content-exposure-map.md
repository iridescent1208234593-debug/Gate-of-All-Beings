## Access Boundaries

- The public fan list filters `is_public=1 AND review_status='approved'` (Fan Review, 2026-11-06) and a `view` partition (art / text / ai); the review queue `/api/fan/review/queue` is reviewer-only and never returns owner ids. The authenticated `/api/fan/my` and `/api/get-characters` routes are separate account paths; their authorization behavior was not retested in this content-only stage.
- Public fan-list JSON previously included `user_kind` and `user_uid` from `SELECT *`, although the checked public page callers use display name/content fields only. The response now preserves those keys as empty strings to avoid exposing account identifiers while keeping the current response shape.
- The unclassified-image page uses only `id` and `reason`; the public list no longer includes the internal `image_path`, source character ID, or timestamp.
- `server/base_static.py` blocks directory listings and sensitive source/database suffixes. The Huiguan handler explicitly maps `/assets/uploads/` to the upload directory, so the path itself is intentionally readable; `robots.txt` does not change that.
- Cloudflare Hotlink Protection, WAF, rate rules, verified-bot handling, and cache rules: **UNKNOWN**. Cloudflare can serve/caches responses without those rules being visible in repository config; no edge behavior is inferred from this source map.

## Derivative Design

Current Gallery production build code copies every discovered `.jpg`, `.jpeg`, `.png`, and `.webp` byte-for-byte into `gallery-files/`; filenames are embedded in the generated client manifest. No original/derivative separation exists in that pipeline. The minimum future design is private source originals → generated public long-edge-limited WebP/AVIF display image → 400px thumbnail, with generated paths referenced by the public manifest. Keep source names/IDs stable only where business links require them; never publish the private-source directory. Do not batch-convert until a representative derivative is visually accepted and the deploy path is verified.

The `assets/uploads` store is shared with avatars and other Huiguan content, so it must not be made private wholesale. First classify which upload families are intentionally public and which represent private account originals; only the latter need an authenticated or short-lived signed delivery path.
