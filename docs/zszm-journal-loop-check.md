# 牌录主循环验证（出发 → 结算 → 照料 → 续读）

对应 [README 路线图](../README.md#路线图) 第一项。目标不是评价玩法乐趣，而是确认**这条主循环在技术上跑得通**：一次出行能结束、结果能写进牌录、过夜能推进日期、刷新后状态还在。

## 固定测试版本

| 项 | 值 |
| --- | --- |
| 仓库 | `iridescent1208234593-debug/Gate-of-All-Beings` |
| 提交 | `3a02c7b`（2026-11-10，`master`） |
| 构建 | `npm run build:cards`，候选位于 `<releases>/candidate/cards` |
| 浏览器 | Playwright + 系统 Edge（headless），视口 1280×900 |
| 输入方式 | 键鼠（脚本点击），未覆盖真机触屏 |
| 初始状态 | 全新存档：第 1 日清晨、见闻 0 条、默认同行者 |

## 运行方式

```powershell
npm run build:cards
npm run verify:journal-loop
# 或指定构建产物位置
$env:IRIDESCENTLY_CARDS_DIR = "<releases>/candidate/cards"
node packages/shared-session/verify-journal-loop.mjs
```

脚本只访问 `127.0.0.1` 上的本地构建产物，外部请求全部拦截，`/api/*` 本地打桩，不接触生产服务。

## 覆盖的四步

| 步骤 | 断言 |
| --- | --- |
| 出发 | 牌录打开在第 1 日 → 选择同行者 → 以「以X启程」进入旅途地图 |
| 结算 | 打完第一场遭遇或折返 → 出现「新的见闻」面板 → 见闻条数增加 |
| 照料 | 过夜推进日期，第 N 日 → 第 N+1 日 |
| 续读 | 刷新页面后日期不回退、见闻不丢失 |

## 已知边界

- **不验证玩法质量**：只说循环跑得通，不说明玩家是否理解后果、是否愿意再来一次。那是路线图第二项的观察任务。
- **只覆盖同行者出行**：重生之门、灵质回路、浅滩未纳入本脚本；三者共用同一本牌录与存档层，但各自的结算分支不同。
- **不覆盖真机**：触屏、横竖屏切换、iOS Safari 的实际表现需要人工验证。
- **战斗为随机对局**：脚本用固定流程（出牌直到结束）推进，不做胜率控制；胜负都会进入结算，因此结果可复现但不保证同一场战斗。

## 后续

需要验证「归来后玩家是否自发改变下一步」时，应在此脚本基础上增加**行为记录**（本次出行的选择、归来后的下一步动作），而不是继续扩展断言。
