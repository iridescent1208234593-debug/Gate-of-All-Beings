# Gate of All Beings 世界观与文案兼容规范

适用范围：所有玩家可见文字，包括 UI、Toast、错误提示、剧情、卡牌、成就、数据描述、README、seed/mock、meta 与分享卡片。

总原则：**众生之门是《罗小黑战记》的同人世界。原作的东西写准，原创的东西写清楚是原创，机制的东西别伪装成世界法则。**

---

## 1. 三层内容

| 层 | 是什么 | 写法要求 |
|---|---|---|
| 原作层 | 原作中出现的角色、地点、组织、概念 | 只写能确认的事实。不确定就少写，或标“推测”。不给原作角色加戏份。 |
| 原创层 | 众生之门自己的设定：门、门庭、众生牌录、重生之门、灵境会馆、西木会馆、OC 等 | 大胆写，但不冒充原作：不用“罗小黑战记·X”格式命名，不用旁白宣布“世界的真相”。 |
| 机制层 | 数值、等级、货币、Boss 阶段、成就 | 用世界观内的中性说法包装，不用修仙/网游等级感，不把规则写成原作设定。 |

## 2. 原作概念（写准）

以下概念来自原作（依据项目自带 worldview 资料，属二手资料）：

- **灵**：万物皆有灵，分物质灵与生灵。**聚灵**是妖精诞生，**散灵**是死亡。
- **妖精**：由灵聚合而生，与人类平等共处是原作基调。不写“妖物、妖孽、斩妖”。
- **灵质空间**：每个生命体固有的空间，衰竭即死亡。不是“开辟的洞天”，也不是货币。
- **灵质力**：能力的统称。
- **能力系**：原作为**六大系**：御灵（金木水火土）、锁御、造物、生灵、心灵、空间（原作/官方设定集相关资料）。强化、治愈等是生灵系下的分支。项目可以有自己的机制分支（如重生之门把强化、治愈单列），但必须标明“本作分类”，不得写成“原作有 N 大系”。项目内的数据文件不高于原作。
- **妖灵会馆**：苍南是**总馆**，其余为分馆（龙游、流石、灵溪等）。执行者、长老（含西木子）是原作设定。
- **法宝、丹药、仙人、神**：原作中存在，但不是妖精的成长阶梯。
- **《众生之门》**：原作漫画中的一款 VR 游戏。本站同名，必须让玩家知道本站是同人作品。

## 3. 原创概念（写清楚）

门、门庭、众生牌录、出行、重生之门、灵质回路、灵质修行、灵境会馆、会馆日常、西木会馆、万灵志、灵卡图鉴、三足乌·虹（OC）、同人角色。

要求：
- 原创地点/组织第一次出现时说明“本站原创”（例：世界地图的西木会馆）。
- 同人角色在任何列表中都要带“同人”标识（万灵志已加；huiguan 主册/副册/同人分开是好的做法）。
- 原创规则写“本作规则 / 本站登记规则”，不写成“世界法则”。

## 6. 分场景原则

**UI**
- 一个东西一个名字，以 [glossary.md](glossary.md) 为准；导航名以 `apps/shell/portal.json` 为唯一数据源。
- 按钮用动词，提示用整句，错误提示说清楚“怎么办”。
- 已下线的玩法名（入世历练、旅途手札、手记、手札）不得出现在玩家可见处。

**剧情**
- 原作角色说话要克制，宁少勿多；自写台词标“同人”。
- 旁白不宣布世界真相；传说、推测用角色口吻。
- 不把两个角色的事迹拼在一起（F01 的教训）。

**建筑与地点**
- 原作地点只写可确认的信息，不赋予“等级”。
- 原创建筑名字可以有特色，但避免“殿、宗、阁”这类门派化后缀成串出现。

**机制包装**
- 数值、阶段、货币用中性词；如果必须用修仙词，限定在“重生之门试炼规则”里，并写明是规则。
- 成就名不以诛杀原作角色为荣。
- 成就、卡牌改名时只改 `name`，不改 `id`，避免影响存档。

## 7. 维护

- 新增文案前先查名词表；新增名词要同步更新名词表。
- 能力系、会馆、角色等世界观数据只在 `packages/shared-data` 和 `packages/shared-types` 维护，各模块读取，不手抄。这些数据以原作为准，本作扩展要标明。
- 描述原作组织时不要写成“完整结构”，例如不要说妖灵会馆“共有 N 处分馆”。
- 不确定的原作设定，在数据里标 `confidence` 或在 UI 标“推测”，不要删除。
