# Gate of All Beings 世界观与文案兼容规范

适用范围：所有玩家可见文字，包括 UI、Toast、错误提示、剧情、卡牌、成就、数据描述、README、seed/mock、meta 与分享卡片。

总原则：**众生之门是《罗小黑战记》的同人世界。原作的东西写准，原创的东西写清楚是原创，机制的东西别伪装成世界法则。**

主创决定见 [decisions.md](decisions.md)。本规范与其中的决定冲突时，以决定为准。

---

## 1. 三层内容

| 层 | 是什么 | 写法要求 |
|---|---|---|
| 原作层 | 原作中出现的角色、地点、组织、概念 | 只写能确认的事实。不确定就少写，或标“推测”。不给原作角色加戏份。 |
| 原创层 | 众生之门自己的设定：门、门庭、众生牌录、重生之门、灵境会馆、西木会馆、OC 等 | 大胆写，但不冒充原作：不用“罗小黑战记·X”格式命名，不用旁白宣布“世界的真相”。 |
| 机制层 | 数值、等级、货币、Boss 阶段、成就、能力分类、五行克制 | 用世界观内的中性说法包装，不用修仙/网游等级感。需要说明时写“本作规则 / 本作分类 / 本作演绎”，不写成原作设定。 |

**怎么判断属于哪一层**

| 问题 | 是 → | 否 → |
|---|---|---|
| 能在原作（动画、漫画、电影、官方设定集）里找到可靠出处吗？ | 原作层，照出处写 | 往下问 |
| 是众生之门自己的地点、组织、身份、角色或叙事吗？ | 原创层，写清是原创 | 往下问 |
| 是为了玩法存在的数值、阶段、分类、克制或资源吗？ | 机制层，标“本作规则” | 列入 decisions.md 的待考证清单，不要自行定论 |

代码里的单一数据来源（`packages/shared-types`、`packages/shared-data`）只保证“项目里只有一份”，不能决定“原作是什么”。

## 2. 原作概念（写准）

以下概念来自原作（依据项目自带 worldview 资料，属二手资料）：

- **灵**：万物皆有灵，分物质灵与生灵。**聚灵**是妖精诞生，**散灵**是死亡。
- **妖精**：由灵聚合而生，与人类平等共处是原作基调。不写“妖物、妖孽、斩妖”。
- **灵质空间**：每个生命体固有的空间，衰竭即死亡。不是“开辟的洞天”，也不是货币。
- **灵质力**：能力的统称。
- **能力系**：原作为**六大系**：御灵（金木水火土）、锁御、造物、生灵、心灵、空间（原作/官方设定集相关资料）。强化、治愈等是生灵系下的分支。项目可以有自己的机制分支（如重生之门把强化、治愈单列），但必须标明“本作分类”，不得写成“原作有 N 大系”。项目内的数据文件不高于原作。
- **妖灵会馆**：苍南是**总馆**，其余为分馆（龙游、流石、灵溪等）。执行者、长老（含西木子）是原作设定。
- **法宝、丹药、仙人、神**：原作中存在，但不是妖精的成长阶梯。
- **《众生之门》**：原作漫画中的一款 VR 游戏。本站与它同名，但不是原作的官方游戏或还原（D01）。在合适的位置简短说明一次即可。

## 3. 原创概念（写清楚）

门、门庭、众生牌录、出行、重生之门、灵质回路、灵质修行、灵境会馆、会馆日常、西木会馆、万灵志、灵卡图鉴、三足乌·虹（OC）、同人角色、**门客**、**灵记**。

**门客**（D13）：曾推开众生之门、被门庭接纳的来访者，是玩家的身份称呼。它不是种族、修行等级、宗门身份、轮回身份或力量等级。

**灵记**（D13）：门客在旅途中留下的记录，承载相遇、选择、成长、同行关系、世界的回应和旅途经历。不能解释成灵魂本体、灵魂碎片、转世凭证、轮回印记或力量等级。

已作废的玩家身份称呼：修行者、魂灵印记、过门人、门印。

要求：
- 原创地点/组织第一次出现时说明“本站原创”（例：世界地图的西木会馆）。
- 同人角色在任何列表中都要带“同人”标识（万灵志已加；huiguan 主册/副册/同人分开是好的做法）。
- 原创规则写“本作规则 / 本站登记规则”，不写成“世界法则”。
- 原作角色的原创招式（如无限的“剑域”“万剑归一”）属于本作战斗演绎：改用贴合已知能力的演绎名，或标“本作演绎 / 原创招式”（D10、D14）。
- 重生之门的轮回、魂灵叙事只是重生之门自己的规则或传说，由门灵、传说或角色口吻表达（D04）。
- 一念仙途是独立的修仙题材外围玩法，与罗小黑世界观没有直接关系（D03）。

## 4. 高风险词

| 风险 | 词 | 处理 |
|---|---|---|
| 修仙等级感 | 炼气、筑基、金丹、元婴、化神、渡劫、境界突破、修为、道心、福缘 | 不用于原作角色和地点；重生之门玩家可见层逐步改为试炼阶段、门内规则、旅程层级（D02、D06） |
| 物种等级 | 妖精→得道→仙人→神、封神 | 不建立统一的物种等级；聚灵阶段描述灵的形成与聚合（D07） |
| 资源化原作角色 | 豪夺、掠夺、克伐（对象为原作角色时） | 原作角色只作来访、请教、切磋、结伴或固定事件（D08） |
| 灵质货币 | 灵质（作货币时）、灵石 | 按用途改为灵材、能量或玩法专属资源（D12） |
| 死亡/诛杀 | 陨落、伏诛、斩妖、除魔、诛杀 | 改“倒下、静养、退场、之战、之试” |
| 贬低妖精 | 妖物、怪物、妖孽 | 改“敌人、失控的灵、对手” |
| 宗门/门派 | 宗门、正魔、门派、长老会（指原创组织时） | 原作组织用原名“妖灵会馆” |
| 网游公告 | 半血狂暴、第二形态、副本、刷怪、爬塔、Boss | 改“被逼到绝境、攻势骤变、试炼、关卡、守门者” |
| 宣布真相 | 世界真相、轮回的真相、魂灵永远不灭、魂灵从未消散、世界的本源 | 改由门灵、传说、门内规则或角色理解来表达（D04） |
| 冒充官方 | 罗小黑战记·X、第N集、EP.N、官方设定 | “X · 罗小黑战记同人”；“（同人短片）”；“官方角色资料” |
| 宗教/造物 | 封神、神之手、超脱轮回、☯ | 中性说法 |
| 开发者腔 | 浏览器、存档槽、mock、数据迁移（玩家可见处） | 世界观内说法或平实说明 |

## 6. 分场景原则

**UI**
- 一个东西一个名字，以 [glossary.md](glossary.md) 为准；导航名以 `apps/shell/portal.json` 为唯一数据源。
- 按钮用动词，提示用整句，错误提示说清楚“怎么办”。
- 已下线的玩法名（入世历练、旅途手札、手记、手札）不得出现在玩家可见处。

**剧情**
- 原作角色说话要克制，宁少勿多。允许同人台词，在模块或区域层标“同人演绎”即可，不用逐句加警告；真正引用原作原句的另注出处（D18）。
- 旁白不宣布世界真相；传说、推测用角色口吻。
- 不把年号、时间表述误读成人物事迹，也不为原作人物附会没有依据的事迹（F01 的教训：“无限63年”是年号，“一剑破城”没有依据）。

**建筑与地点**
- 原作地点只写可确认的信息，不赋予“等级”。地点可以作为路线、楼层、关卡、试炼节点（D06）。
- 原创建筑名字可以有特色，但避免“殿、宗、阁”这类门派化后缀成串出现。

**机制包装**
- 数值、阶段、货币用中性词；如果必须用修仙词，限定在“重生之门试炼规则”里，并写明是规则。
- 系别与五行的对应、玩法里的能力互斥等，写明是“本作演武规则 / 玩法平衡规则”（D16、D17）。
- 角色的平衡档位只作为内部数值，不向玩家显示，不用修仙境界命名（D05）。
- 改名只改玩家可见语义，不重构存档契约；内部字段保持兼容。
- 成就名不以诛杀原作角色为荣。
- 成就、卡牌改名时只改 `name`，不改 `id`，避免影响存档。

## 7. 维护

- 新增文案前先查名词表；新增名词要同步更新名词表。
- 能力系、会馆、角色等世界观数据只在 `packages/shared-data` 和 `packages/shared-types` 维护，各模块读取，不手抄。这些数据以原作为准，本作扩展要标明。
- 描述原作组织时不要写成“完整结构”，例如不要说妖灵会馆“共有 N 处分馆”。
- 不确定的原作设定，在数据里标 `confidence` 或在 UI 标“推测”，不要删除。
