# 测试、运营与审核、版权与资料、项目管理

这四个组的工作量都不大，可以由一两个人兼任。其中版权登记要最先开始，否则素材进了游戏也说不清是谁的。

## 测试

- [ ] P0 每次出新版，都在三台设备上走一遍固定的检查清单。设备是电脑浏览器、一台 iPhone、一台安卓手机。清单包括：
  - 每个出口
  - 每个 NPC
  - 每个可以点的东西
  - 存档后关掉再打开
- [ ] P0 记 Bug 用统一的模板，每条写清：
  - 设备、浏览器
  - 做了什么
  - 看到了什么
  - 本来应该是什么
  - 截图或录屏
  - 严重程度，分四级：打不开或丢档、卡住走不下去、看得出的错、小瑕疵
- [ ] P1 弱网加载、低端机帧率、不同屏幕比例。

**验收**：每个版本附一份测试结果，列出通过项、不通过项、可以复现的问题和负责修的人。

## 运营与审核

- [ ] P0 定画廊和 OC 投稿的审核标准：哪些算无关图片、AI 图、擦边、盗图，各自怎么处理。
- [ ] P0 定举报流程：受理、复核、申诉，每一步谁负责、多久内答复。
- [ ] P1 OC 故事征集和 NPC 投稿活动，以及给作者的回复模板。

**验收**：每个投稿和举报都有状态和负责人，可以查到处理结果。

## 版权与资料

- [ ] P0 建素材台账，格式见 [general.md](general.md)。先把已经进游戏的素材补登：
  - 美术组的作品
  - 两个开源包：painted-characters 和 3D-Pixel-Campfire，都是 MIT 许可
  - Noto Sans SC 字体，OFL 许可
- [ ] P0 请每位美术老师书面确认两件事：作品可以用在游戏里，以及署名怎么写。
- [ ] P0 把 AI 使用规则（见 [general.md](general.md)）发给所有老师，确认每人都知道。
- [ ] P1 NPC 投稿协议、撤稿下架流程、隐私政策、版权投诉流程。

**验收**：游戏里任何一张图、一段声音，都能查到作者、来源和授权范围。

## 项目管理

- [ ] P0 每个组定一名负责人和一名备用联系人。
- [ ] P0 建一张统一的任务表，每行写清：
  - 任务
  - 负责人
  - 状态（用 [general.md](general.md) 里的五种）
  - 截止日
  - 交付位置
  - 做完交给谁接着用
- [ ] P1 每周汇总一次：交了什么、卡在哪、下周做什么。

**验收**：任何一位老师都能说出自己手上的任务、交付标准，以及做完交给谁。
