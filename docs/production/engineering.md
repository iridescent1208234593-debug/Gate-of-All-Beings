# 程序相关组

客户端的地图部分有一半已经在原型里做好，程序组接着做剩下的部分即可。原型在本机 `labs/zszm-godot-map`（暂不在仓库里），说明在它的 README。

## Godot 客户端

**已经有了**：

- 移动与镜头：点哪走哪（可以斜着走），镜头跟随和缩放。
- 场景：碰撞，树和屋顶的前后遮挡。
- 交互：调查、对话、拾取，经过时触发的事件。
- 地图：四张图之间切换，昼夜。
- 特效：篝火、风吹树叶等。
- 发布：网页导出，横屏。
- 测试：一套 57 项的自动走查。

- [ ] P0 主菜单、暂停、设置（音量分三项）。

## 后端与网站

游戏和网站之间已经有一套消息协议：游戏只发互动编号，由网站回答内容、记下状态（见 `docs/zszm-identity-and-save-map.md`、`docs/game-save-ownership.md`）。账号、身份（OC）、手记、存档都归网站管，游戏不另建一套。

- [ ] P0 定下游戏存档的数据格式（含版本号），做好四件事：写入、读取、旧版存档升级、写失败后的恢复。
- [ ] P0 网站里放游戏的页面：启动、加载、返回。
- [ ] P0 网站安全策略放行游戏（**待负责人批**）：网站现在的安全策略（CSP）一旦改为强制，会拦住游戏。需要只在游戏页面加上 `'wasm-unsafe-eval'`。
- [ ] P0 游戏里的互动文字改由网站下发，这样文案改字不用重新打包游戏。
- [ ] P1 数据服务：任务、卡牌、物品、NPC；以及公共世界和个人分支的状态存储。
- [ ] P1 游戏文件走 CDN 并压缩：
  - 引擎文件压缩后约 10 MB。
  - 每个版本测一次弱网下的加载时间。

**验收**：在独立的测试环境里完成存、读、断线重连和恢复，不碰正式数据。

## 服务器与安全

维持现有做法：开发、测试、正式三个环境分开，发布可以回滚，生产变更要负责人授权。

游戏上线前要补的是：

- 游戏静态文件的缓存和压缩
- 存档接口的限流和权限校验
- 一次备份恢复演练
- 所有账号开启两步验证
