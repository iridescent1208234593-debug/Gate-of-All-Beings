# 西木会馆 × B站 Toy 接入方案

写于 2026-11-04。平台规则摘自下列来源当天的内容，平台随时可能调整，发布前以 Toy 发布平台和官方公告为准：

- 官方 Toy JS SDK 能力清单（2026-09-18 版）与 `toy.d.ts`，负责人提供，存于 `E:\Bilibili Toy`；
- Toy 开发者 FAQ：<https://www.bilibili.com/opus/1241171666570051585>；
- 官方 CLI 与发布技能：<https://github.com/bilibili/toy>（提交 `faee502`，2026-11-03），含 `skills/toy/references/content-checklist.md`；
- 平台介绍：<https://www.bilibili.com/toy/intro>。

## 一、可行性结论

**能接入，但不能按"Toy 跳转到会馆网站"的方式接入。** Toy 平台明确禁止站外跳转和站外引流，SDK 也没有任何打开外部网址的能力。合规的做法是：Toy 做一个独立的、纯静态的西木会馆门庭页，只在 B站 站内互相导流；会馆网站保持现状、自己经营自己的入口。

| 问题 | 平台规则 | 对本项目的含义 |
| --- | --- | --- |
| 能否跳到外部网站 | FAQ 禁止项："不得跳转站外链接"；站外跳转标准同个人主页和视频简介。`toy.navigate` 只支持 `video / space / search / opus / tribee / toy` 六类 B站 站内页面；`share`、`getQrCode` 只能指向当前 Toy 内页面 | Toy 里**不放**会馆域名、二维码或"去网站注册"之类文字；拒审最常见的原因就是引导站外注册 |
| 能否用 iframe 嵌入会馆 | FAQ："Toy 不能通过 iframe 外链其他网页" | 不能把现有站点套进 Toy |
| 能否调会馆后端 | 自有后端 / 自定义接口需要事先申请权限；外部资源"后续会收紧" | 门庭页不调任何会馆接口，也就不暴露部署地址和 API |
| 登录与用户内容 | 只能用 B站 账号；禁止第三方登录；类 UGC 能力（聊天、自由文本、上传）基本不允许；用户昵称头像只能来自 SDK | 会馆的账号、人设登记、上传都**不能**搬进 Toy |
| 包限制 | 入口 `index.html` 解压后 ≤ 1MB；整包默认 ≤ 50MB；页面跑在 `/toy/<slug>/` 下，资源必须用相对路径 | 门庭页约 7KB，远低于限制 |
| 账号与归属 | CLI 用 `toy login` 走 B站 OAuth；每个账号只管理自己的 Toy；只能把自己账号的视频绑到自己的 Toy；FAQ 未提供团队 / 多作者协作机制 | 必须由项目方账号创建和发布，第三方没有可用的正式协作通道 |
| 更新、撤回 | 可无限次更新；可见性可在 `public / link-only / password` 之间切换；slug 发布后不可改；CLI 无删除命令，下架走审核咨询入口 | 撤回不依赖任何第三方 |
| 商业化 | 不支持支付、广告 SDK；禁止站外收款 | 门庭页不含任何付费或引流到站外收款 |

"西木会馆小站"按 B站 小站（SDK 的 `tribee` 类型）理解：Toy 可以直接跳过去。如果负责人指的是自己网站上的一个页面，那么它只能由网站自己的渠道去推广，Toy 不能链接它。小站和个人空间自身能否写网站地址，受 B站 社区规则约束，这次没有核实，负责人在 B站 后台操作时以页面提示为准。

## 二、推荐架构与实施步骤

```
B站 站内                                       会馆自有（不变）
┌──────────────┐  navigate   ┌──────────────┐   ┌───────────────────────────┐
│ Toy 门庭页   │ ──────────▶ │ 项目方空间 / │   │ 西木会馆网站 + 服务器      │
│ 静态包 7KB   │ ◀────────── │ 小站 / 视频  │   │ 三根域、账号、数据、管理   │
│ 项目方账号发 │  视频挂入口 └──────────────┘   │ 完全独立，Toy 不访问       │
└──────────────┘                                 └───────────────────────────┘
```

- 源码在仓库 `apps/bilibili-toy/`（内容 `content.json`、图片登记 `assets/assets.json`、模板 `src/`），构建与安全检查在 `tools/toy/build-toy-bundle.mjs`。源码归项目方 GitHub 仓库所有，谁都能从仓库重新构建。
- 构建产物写到仓库外的目录，由负责人用项目方 B站 账号上传。
- 页面只调用三项 SDK 能力：`isSupport`、`navigate`（站内跳转）、`getQrCode`（桌面端显示本 Toy 首页二维码，方便换手机看）。不读取用户资料、不用云存储、不收集任何数据。
- 不在 B站 App / Toy 页面里时（本地预览、普通浏览器），跳转按钮自动禁用并提示。

实施步骤：

1. 负责人确认本方案与页面文字（`content.json` 里的介绍、项目列表、免责声明）。
2. 负责人填写 `content.json` 的 `publisher`、`bilibili.spaceMid`（发布账号 UID）、可选 `tribeeId` 与介绍视频 BV 号；决定是否放图，放图则按授权登记进 `assets/assets.json`。
3. 合并分支（经评审），按 `apps/bilibili-toy/README.md` 用 `--release` 构建。
4. 负责人用自己的账号预览、提交审核、首发 `link-only`，确认后改 `public`。
5. 负责人用 `toy video bind` 把介绍视频挂上 Toy 入口。

## 四、项目方自行操作的发布流程

具体命令见 `apps/bilibili-toy/README.md`，要点：

1. 只在项目方自己的电脑上 `toy login`，浏览器里登录项目方 B站 账号；`toy whoami --json` 核对账号。登录会话保存在本机，不发给任何人。
2. `toy create <包目录> --json` 只上传并返回预览链接，**不加 `--yes` 不会提交审核**。手机 B站 App 和电脑各打开一次预览。
3. 预览无误再同参数加 `--yes`。首发可见性 `link-only`。
4. 审核通过后改 `public`，绑定视频。
5. 每次更新：从仓库最新提交构建新包 → `toy update <id> <包> --json` 预览 → 确认后 `--yes`。

发布前自检（负责人或开发者都可做，不需要账号）：

- `node tools/toy/build-toy-bundle.mjs --check <包目录>` 通过；
- 官方预检 `skills/toy/scripts/toy_doctor.py <包目录>` 无 ERROR（本次在云端环境中没有运行它，需在本机跑一次）；
- 手机 390px 宽、电脑 1280px 宽打开预览，无横向滚动，按钮能跳转。

## 五、账号、版权与控制权风险检查表

每次发布前逐项打勾。

**账号与发布权**

- [ ] Toy 由项目方 B站 账号创建；`toy whoami` 显示的是项目方账号，不是任何开发者个人账号。
- [ ] 没有任何人向第三方提供过项目方 B站 账号密码、Cookie、Token 或 `toy login` 会话文件。
- [ ] 第三方只交付源码 / 包目录；上传、提交审核、改可见性、绑定视频全部由负责人操作。
- [ ] 项目方账号开启了 B站 登录保护（手机绑定、二次验证），恢复方式只在负责人手里。
- [ ] B站 上不存在由第三方账号发布的西木会馆 Toy；若发现，要求对方撤下，必要时向平台申诉。

**代码与内容所有权**

- [ ] Toy 源码在项目方 GitHub 仓库，第三方的仓库权限可随时撤销而不影响 Toy。
- [ ] Toy 标题、简介、页脚写明发布方是西木会馆项目方，没有把项目登记为开发者个人作品。
- [ ] 进包的每张图都登记在 `assets/assets.json`，作者明确；协作者的作品有书面授权，未授权的不放。
- [ ] 同人声明保留："罗小黑战记相关 IP 版权归寒木春华动画工作室所有"与免责声明；不使用官方原画、截图或官方标志。
- [ ] 非商业：无付费、无广告、无站外收款。

**安全与数据**

- [ ] 安全检查通过：包里没有三根域任一域名、部署地址、IP、API 路径、管理入口、密钥或 `.env`。
- [ ] 包里没有完整网站源码、数据库、后台、用户数据或服务器配置。
- [ ] Toy 不收集用户数据；若以后用到 `getUserProfile`，`toyOpenId` 不写日志、不当作会馆账号。

**平台合规**

- [ ] 无站外链接、无 iframe、无第三方登录、无自由文本输入或上传。
- [ ] 入口 `index.html` < 1MB，整包 < 50MB，全部相对路径。

## 六、更新、撤回、下架与迁移

| 场景 | 做法 | 能否独立完成 |
| --- | --- | --- |
| 更新内容 | 改 `content.json` → 提交到仓库 → 构建 → `toy update` 预览 → `--yes` | 负责人独立 |
| 回滚到旧版 | 检出旧提交重新构建，再 `update` 一次 | 负责人独立 |
| 暂时撤回 | 可见性改 `password` 或 `link-only`，广场不再展示；改回 `public` 恢复 | 负责人独立 |
| 彻底下架 | CLI 无删除命令；在发布平台网页查找删除 / 下架功能（未核实），否则走 FAQ 所说的审核咨询入口 | 负责人独立，依赖平台流程 |
| 解绑视频 | `toy video unbind`，即时生效，可再绑回 | 负责人独立 |
| 第三方退出 | 撤销其仓库权限；他从未持有账号会话，无需交接；Toy 照常运行 | 负责人独立 |
| 换发布账号 | 平台未提供 Toy 转移机制（FAQ 未提及），只能新账号重新发布（新 slug），旧 Toy 改 `password` 后申请下架 | 负责人独立 |
| 迁出 Toy | Toy 只是静态门庭页，不承载任何数据；下架即结束，网站与数据不受影响 | 负责人独立 |
| 网站迁移 / 换域名 | 与 Toy 无关，Toy 里本来就没有域名 | 不涉及 Toy |
