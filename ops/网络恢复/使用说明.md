# 国际漫游后恢复网络

关掉手机 USB 网络共享或拔下数据线，确认电脑已连回正常 Wi-Fi/有线网络，保持 Clash Verge 的 TUN 模式开启。双击桌面的“国际漫游后恢复网络.cmd”，看到“已完成并验证”才表示处理成功。失败时日志会给出原因，不会假报成功。

脚本通过现有 Mihomo 本地命名管道启用 strict-route、自动路由/接口检测以及 UDP/TCP DNS 劫持，清除 Mihomo 和 Windows DNS 缓存。TUN 设置变化可能引起短暂网络重连。不会禁用网卡、重置 DHCP/Winsock、关闭 IPv6，或修改语言/指纹/代理节点/DNS 上游配置；国内 DIRECT DNS 保留。

这里应用的是运行时配置，Clash 重启、订阅更新或配置重新应用后可能被覆盖。切换网络之后再次运行即可。不直接编辑 Clash 生成的 YAML。

运行之后关闭旧检测页面，重新打开 https://www.dnsleaktest.com/ 执行 Extended Test，再看 https://ipleak.net/ 。脚本验证配置是否生效，不能代替外部 DNS 泄漏测试，也不能保证所有 DNS 结果都属于同一国家。仍出现中国移动时，应结合查询日志检查规则和浏览器安全 DNS，不能据此直接认定手机网卡是来源。

日志和修改前 TUN 状态在 logs/。只读诊断：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\Projects\ops\网络恢复\恢复网络.ps1" -DiagnoseOnly
```

恢复最近一次运行前的 TUN 状态：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "E:\Projects\ops\网络恢复\恢复网络.ps1" -Restore
```

严格路由是 Mihomo 官方 Windows 多网卡 DNS 泄漏防护机制，可能影响某些虚拟机联网。文档：https://wiki.metacubex.one/config/inbound/tun/#strict-route
