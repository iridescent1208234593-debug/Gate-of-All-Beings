# 西木会馆账号系统说明

更新日期：2026-08-06 · 适用站点：huiguan.iridescently.xyz（试点）

## 一、这次更新了什么

原来站点只有 USSO 第三方登录，没有注册、没有管理后台，登录态存在内存里一重启就丢。这次在不引入任何第三方依赖的前提下（纯 Python 标准库 + SQLite），补齐了一套自有的轻量账号系统：

- 访客可以用「用户名 + 密码」直接注册、登录，30 秒完成
- USSO 外部登录暂时停用；既有 USSO 用户资料、权限和角色数据保留
- 登录态持久化到 SQLite，服务重启不再掉线（有效期 30 天）
- 新增管理后台 `/admin.html`：用户列表、封禁/解封、升/降管理员、删除用户
- 你的 USSO 账号（ID=7）永远是管理员，不受任何操作影响

同时顺手修了三个老问题：

1. 前端调 `/api/huiguan/*`、后端路由却是 `/api/*`，导致**角色卡云同步一直是 404**——现在后端做了兼容映射（两种路径都认），前端也已修正。
2. OAuth 回调地址声明 `/cb` 但处理器只认 `/`——现在 `/`、`/cb`、`/api/callback` 三个路径都能接住回调。
3. **安全漏洞**：原来 `.py`、`.db`、`.log` 文件都能被直接下载，等于把含 USSO 密钥的源码和全部用户数据挂在公网。现在这类文件一律返回 404。

## 二、架构概览

```
访客浏览器
   │  https://huiguan.iridescently.xyz
   ▼
Cloudflare 隧道（cloudflared）
   │  http://localhost:8089
   ▼
server_huiguan.py（Python 标准库，单文件）
   ├── users.db（SQLite）：用户资料 / 站内账号 / 会话 / 管理标记
   └── characters.json：角色卡数据（按用户分组）
```

涉及文件（都在 `%USERPROFILE%\www_huiguan\`）：

| 文件 | 作用 |
|---|---|
| `server_huiguan.py` | 后端全部逻辑：静态文件、USSO OAuth、注册/登录、管理接口 |
| `index.html` | 前端：右上角「登录 / 注册」弹窗、角色卡同步 |
| `admin.html` | 管理后台页面（仅管理员可用） |
| `users.db` | SQLite 数据库，4 张表（见下） |
| `characters.json` | 角色卡数据，登录用户按 uid 分组存储 |

## 三、账号体系怎么运作

**当前登录方式：**

- **站内账号（单框设计）**：弹窗里只有一个用户名框 + 一个密码框，按钮是「登录 / 注册」。后端自动判断：用户名已存在 → 校验密码登录；不存在 → 直接注册并登录（按钮下有提示文案）。用户名 2-16 位中英文/数字/下划线，密码 6-64 位，密码用 scrypt 加盐哈希存储，数据库里查不到明文。注意手滑风险：登录时把用户名打错（且错的名字不存在）会注册出一个新账号，发现角色卡是空的就退出重登，错号可在管理后台删掉。
- **USSO 登录**：当前暂停新授权和回调；既有用户资料、权限和角色记录不删除。跨站 `hx_sso` 会话与 USSO 登录是两套机制，本次没有停用前者。
- **邮箱验证**：账户页可绑定新邮箱；验证链接仅在会馆站内登录态下使用，30 分钟过期且一次有效。绑定关系单独存入 `account_emails`，不会把 USSO 资料邮箱自动提升为已验证。

**身份区分**：每个会话都记 `kind`（`local` 站内 / `usso`）+ `uid`。站内用户在角色卡数据里的键是 `local:<uid>`，USSO 用户沿用原 ID（你的是 `7`），互不冲突。

**身份体系（执行者 / 长老 / 管理员）：**

- **执行者**：注册账号的默认身份。御灵系最多可选 2 系，年龄上限 450 岁。
- **长老**：在执行者基础上年龄上限提升到 1500 岁（御灵系仍 2 系）。获得方式二选一：① 本人在表单页点「申请长老」提交申请，管理员在后台「长老申请」里同意；② 管理员直接在用户列表里「设为长老」。
- **管理员**：站点管理权限（用户管理、审批长老、删卡等）。`ADMIN_USSO_IDS = {"7"}` 里的 USSO 用户永远是管理员（你）；站内账号 `role='admin'` 也是管理员。
- 未登录访客：御灵系最多 1 系、年龄上限 450 岁（鼓励注册）。
- 表单页的身份状态行（御灵系区块内）会实时显示当前身份与权限，并在执行者身份下给出「申请长老」按钮；导航栏用户名旁也有身份小标签。
- 兜底规则：如果全站一个管理员都没有，第一个注册的人自动成为管理员（正常情况下不会触发，因为你始终在）。

**限流（防刷）：**

- 同一 IP 每小时最多注册 5 次
- 同一用户名 + IP，10 分钟内登录失败 8 次后锁定 10 分钟

## 四、数据库结构（users.db）

| 表 | 内容 |
|---|---|
| `users` | USSO 登录过的用户档案（原有表，未动）：user_id / nickname / email / picture / first_login / last_login |
| `local_users` | 站内注册账号：uid / username（唯一，不区分大小写）/ pass_hash（scrypt$盐$哈希）/ nickname / role（executor 执行者 / elder 长老 / admin 管理员）/ status（active/banned）/ created_at / last_login |
| `sessions_db` | 会话持久化：sid / kind / uid / created_at / expires_at。重启不丢登录态的关键 |
| `user_flags` | USSO 用户的管理标记（封禁、提权用）：kind / uid / status / role |
| `elder_requests` | 长老申请：id / kind / uid / name / message / status（pending/approved/rejected）/ created_at |

角色卡数据在 `characters.json`，结构不变：`{ "用户key": [ {code, html, data}, ... ] }`。

## 五、接口一览

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth` | **统一入口（前端单框用）**：用户名已存在→校验密码登录；不存在→直接注册并登录。返回带 `registered` 标志，前端据此显示"登录成功"或"已自动注册并登录" |
| GET | `/api/login` | USSO 登录暂停时返回 410；仅完成迁移并显式开启后才跳转授权 |
| GET | `/api/account/email` | 当前会话的已验证邮箱状态 |
| POST | `/api/account/email/send` | 发送一次性邮箱验证链接 |
| POST | `/api/account/email/verify` | 验证链接并绑定邮箱 |
| POST | `/api/login` | 纯登录（独立接口，保留）：`{username, password}`，成功返回用户信息并种 cookie |
| POST | `/api/register` | 纯注册（独立接口，保留）：同上格式，用户名已存在返回 409 |
| GET | `/api/user` | 当前登录态：logged_in / kind / username / nickname / role / is_admin |
| GET | `/api/logout` | 退出登录，302 回首页 |
| GET | `/api/get-characters` | 取自己的角色卡（需登录） |
| POST | `/api/save-character` | 保存单张角色卡（需登录） |
| POST | `/api/save-all-characters` | 全量同步角色卡（需登录） |
| GET | `/api/get-character?code=` | 公开的角色展示页数据（无需登录，原有） |
| GET | `/api/admin/users` | 管理员：全部用户列表 |
| POST | `/api/admin/user/update` | 管理员：`{kind, uid, set:{status?, role?}}` 封禁/提权 |
| POST | `/api/admin/user/delete` | 管理员：删用户及其角色卡数据 |

兼容处理：`/api/huiguan/xxx` 会自动映射到 `/api/xxx`，旧代码不会 404。

## 六、管理后台怎么用

1. 用你的 USSO 账号（或任何管理员账号）登录后，右上角会出现「管理」按钮，点进去就是 `/admin.html`
2. 列表展示所有用户：来源（站内/USSO）、用户名、邮箱、角色、注册时间、最近登录
3. 每行操作：**封禁/解封**（被封禁者立即掉线且无法再登录）、**设为管理员/取消**、**删除**（连同角色卡一起删，不可恢复，有二次确认）
4. 不能对自己执行封禁/降级/删除（防止误操作把自己锁在外面）
5. 未登录或非管理员访问该页会被拒绝

## 七、服务管理（运维备忘）

**启动**（已在用，供参考）：

```powershell
Start-Process python -ArgumentList "server_huiguan.py" -WorkingDirectory "%USERPROFILE%\www_huiguan" -WindowStyle Hidden -RedirectStandardOutput "%USERPROFILE%\www_huiguan\server_huiguan.log" -RedirectStandardError "%USERPROFILE%\www_huiguan\server_huiguan.err.log"
```

**重启 = 先杀旧进程再启动**。这次踩过的坑：旧进程是管理员权限启动的，普通终端杀不掉（提示"拒绝访问"），必须**右键以管理员身份打开终端**执行：

```bat
taskkill /PID <进程号> /F
```

**警惕双进程**：Windows 上 Python 的 HTTPServer 允许重复绑定同一端口，两个进程可以同时"监听" 8089，请求随机落到新旧两个进程上，症状是时好时坏。启动前先用 `netstat -ano | findstr :8089` 确认没有残留进程。

**改完代码必须重启进程才生效**（静态 HTML/CSS/JSON 改完即时生效，`.py` 不行）。

| 配置 | 当前值 | 说明 |
|---|---|---|
| `ADMIN_USSO_IDS` | `{"7"}` | 永久管理员的 USSO ID 集合 |
| `SESSION_DAYS` | 30 | 登录态有效天数 |

| `ACCOUNT_EMAIL_SMTP_USER` | 空 | 发信邮箱账户 |
| `ACCOUNT_EMAIL_SMTP_PASSWORD` | 空 | 发信邮箱的客户端授权码/凭据，必须仅由运行环境提供 |
| `ACCOUNT_EMAIL_FROM` | 与 SMTP 用户相同 | 邮件显示的发件地址 |
| `ACCOUNT_EMAIL_BASE_URL` | 会馆账户页 | 验证链接回跳地址 |

## 九、安全说明

**已做：**

- 密码 scrypt 加盐哈希（个别环境自动降级 pbkdf2），常量时间比较防时序攻击
- Cookie：HttpOnly + SameSite=Lax，HTTPS 环境自动加 Secure
- 敏感文件（.py / .db / .log / characters.json / 隐藏目录）禁止静态下载
- 注册、登录限流；OAuth state 校验；管理员接口全部校验身份
- 被封禁用户的已有会话立即失效

**后续事项：**

- USSO 外部登录目前被 `USSO_LOGIN_ENABLED=0` 关闭；用户映射和既有数据保留。跨站 `HX_SSO_SECRET` 签发不受此开关影响。
- 邮箱绑定需要配置发信邮箱的 SMTP 凭据；未配置时不会创建“已验证”状态。现有找回问题流程仍保留，已验证邮箱当前还没有接入密码重置。
- 重要操作（如删用户）可以考虑加操作日志表

## 十、如何复制到其他子站（zszm 等）

这套代码刻意保持单文件、零依赖，就是为了方便复制：

1. 把 `server_huiguan.py`、`admin.html` 复制到目标站目录，改 `PORT`、`CALLBACK_URL`（如需 USSO）
2. 前端把 `index.html` 里「登录弹窗 CSS + 弹窗 HTML + 登录 JS 区块」三段拷过去
3. 注意每个站目前各有独立 users.db，账号不互通——如果以后想要五站统一登录，把账号模块抽成独立的 `account.iridescently.xyz` 中央服务即可，本次的数据结构已为此留好余地（kind/uid 设计）

## 十一、常见问题

**Q：curl/脚本访问接口报 403 error code: 1010？**
这是 Cloudflare 的浏览器完整性检查拦了非浏览器 User-Agent，换成浏览器 UA 即可；真实用户在浏览器里不受影响。

**Q：重启服务后用户会掉登录吗？**
不会了。会话存在 SQLite 的 `sessions_db` 表里，重启后自动恢复。

**Q：忘了管理员密码怎么办？**
用 USSO 登录（你是永久管理员），或者直接用 sqlite 工具改 `local_users` 表的 `role` 字段。

**Q：用户名会重名吗？**
不会。`username` 字段是唯一索引且不区分大小写（`Jialin` 和 `jialin` 视为同一个）。不过统一入口的逻辑是"用户名已存在就走登录"，所以正常人不会撞到重名报错；只有并发抢注同一名字的极端情况才会触发 409。

**Q：登录时打错用户名，会不会误注册一个新号？**
会——这是"一个框自动判断"的取舍。打错的名字若不存在，系统就当新账号注册了。识别办法：登录后发现昵称不对 / 角色卡是空的，说明进错号了，退出用正确的用户名重新登录即可，误建的空号管理员可在后台删掉。弹窗按钮下已加了"用户名不存在时将自动注册并登录"的提示文案。

**Q：能改用户名规则 / 密码长度吗？**
在 `server_huiguan.py` 里搜 `USERNAME_RE` 和注册校验那一段，改完重启服务。

**Q：改动历史在哪看？**
`%USERPROFILE%\www_huiguan` 是 git 仓库，本次改动前的备份另存于工作区 `backup_huiguan_20260806`。
