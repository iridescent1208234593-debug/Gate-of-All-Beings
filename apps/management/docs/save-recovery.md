# 灵境会馆存档恢复

- 游客使用独立的访客槽位。点击登录或退出前，只保存旧账号的本地状态；停止模拟及写入，加载目标账号自己的云档或本地档，再恢复模拟。不把之前会话中的进行中进度复制到目标账号。新账号确实无档时新开一局。
- 有效云档仍优先，有效本地档仍可作为回退。云接口仅当明确返回「暂无云存档」才视为空；网络失败、非预期响应或损坏不视为空槽。任何来源异常时显示具体原因，保留原档并暂停手动、自动、离开页面和交换收获的写入，共享状态不被当成空档覆盖。恢复联网后重进模块，重新确认源档状态。
- 保留原有本地槽位、JSON 外层与云 API。兼容 `0.1.0` 与 `0.2.0`，有必要字段的旧档无需迁移，即使某个新版扩展字段缺失；关键字段缺失或版本未知则保留、不猜测补写。发布回滚只需还原代码，不需要数据迁移回滚。离线临时游玩的进度不会合并进一个版本未知的云存档。
- 本次测试覆盖当前模块内的账号切换和同一来源的已确认退出。没有改变历史的本地 UID 槽位命名；跨身份提供方 UID 冲突及跨标签页同时改变服务器 cookie 属于不同边界，若需在启用第二身份提供方后支持需另审数据兼容与服务端原子约束。

使用 `node --test apps/management/tests/save-game.test.js` 验证本地格式、云接口回退与重新联网、账号切换和退出保护；测试只使用进程内存储及假服务。模块回归 `npm test --prefix apps/management`。
