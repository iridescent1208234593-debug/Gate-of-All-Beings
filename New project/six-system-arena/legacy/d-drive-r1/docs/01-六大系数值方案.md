# 01 · 六大系数值方案（可实行方法）

> 本文补齐 `src/world/rating.js` 头部引用的 `docs/01-六大系数值方案.md`（此前缺失）。
> 读者对象：需要把 v4 库角色接进 zszm 数值系统的开发者。

## 1. 结论先行：三条可实行路径

| 路径 | 做什么 | 成本 | 推荐场景 |
| --- | --- | --- | --- |
| **A. 只读派生 + JSON 投影**（本轮已落地） | 脚本只读 v4 库 → 输出 `data/character-stats.json` | 低 | 先把数值口径与可视化稳定下来，不动 DB |
| **B. 模块引用（zszm 直接 import）** | zszm 通过 `@lxh/six-systems` 引用 `src/world`、`src/ui` | 低 | zszm 侧渲染雷达/条形/徽章，零拷贝、零构建依赖 |
| **C. 写回 DB / 独立数值库** | 把分值落到 `character_stats` 表或新库 | 中 | 需要与其他系统共享数值、需要 SQL 侧排序筛选时 |

本轮选 A（并已把 B 的接口做好），C 留待口径稳定后再评估——理由是**分值全部为 `provisional=true`**，过早写库会让"可推翻"变成"难推翻"。

## 3. 数值派生模型（derive-full-v2.0.0）

单系分值域固定 **0..100**，由六项加分构成后裁剪：

| 项 | 上限 | 依据 |
| --- | --- | --- |
| base | 6..20 | `FNV-1a(name#systemId)` 确定性散列，保证同输入同输出、无角色全 0 |
| 存在分 presence | 30 | 该系在 `abilities_summary / notes / story_summary / species / residence` 中出现 |
| 复现分 repeat | 10 | 同一系在文本中重复命中（每次 +5，封顶 10） |
| 具名分 named | 24 | 能力条目里出现「X系·分支」结构化写法（每次 +8，封顶 24） |
| 分支分 branch | 20 | 命中该系具名分支关键词（每次 +5，封顶 20） |
| 叙事分 narrative | 15 | 剧情摘要中的强叙事线索（每次 +5，封顶 15） |

特殊规则：

- **空间系归零规则**：空间系无法后天习得。当「X系」提及、具名分支、分支关键词三项全为 0 时，空间系分值强制归零。
- **五行属性**：取五行关键词命中次数最多者，全为 0 记 `none`；与六大系互不影响。
- **境界**：DB 无「角色→境界」字段，由 `category / species / deity` 推断（渡劫 > 化神 > 凡俗 > 未判定），并在 README 标注为推断值。
- **评级**：`composite = peak×0.5 + average×0.3 + secondary×0.2`（不看六系总分，避免"多修一系白送分"）；`power = composite + 境界加成`，上限 150。

## 4. 可追溯性（为什么敢用）

每条角色记录都带 `evidence`：命中关键词、来源表、原文片段、`innateZeroed`、文本长度与 `confidence` 分级（`tagged` > `textual` > `baseline`）。

- 想推翻某个角色的分数：查 `evidence.matchedKeywords` 与 `abilitySnippets` 即可定位到具体字段。
- 想整体重算：`node tools/derive-all-stats.mjs`；想校验当前 JSON 未被手改：`node tools/derive-all-stats.mjs --check`。

图标选型红线：只做 **UI 图形**（字形 + 圆环 + 配色），**禁止 AI 生成角色形象**。

## 6. 与 zszm 现有框架的接法

`zszm/src/game/core/types.ts` 的 `Card` 已有 `school?: AbilitySystem`、`element?: Element`、`glyph` 字段，因此：

1. 数值层不需要改 `Card` 结构，只需在卡组分配阶段读 `data/character-stats.json` 的 `systems` 与 `skillTags`；
2. 卡面渲染把纯文字系名替换为 `systemIcon(school)`，即可获得图标化；
3. `buildDuelBarsSVG` 可直接用于对局前的双方战力对照面板。
