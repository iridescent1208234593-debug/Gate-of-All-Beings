---

## 1. 定位

R2 的失败结算直接内联了 2 张安慰图；R5 把「表情图从哪来、谁审的、能不能用」拆成一份**外置台账**：

| 关注点 | R2 做法 | R5 做法 |
| --- | --- | --- |
| 图池来源 | 硬编码在 `settlement.js` | `data/emoticons.json` 登记，引擎 `loadEmoticons()` 注入 |
| 官方渠道 | 未登记 | `channels` 段登记 5 条官方发行渠道 |
| 逐张审查 | 注释留痕 | `review_log` 段逐张留痕（日期 / 审查方 / 结论 / 依据） |
| 未采集项 | 无 | `pending` / `unresolved` 段显式挂账 |
| 合规校验 | 人工看 | `validate_achievements.py` 校验段 D + `smoke_test.js` 断言 |

**可扩展性**：后续新增表情图只改台账 JSON，不动引擎代码；引擎侧只做**正向白名单校验**（路径必须落在官方素材库的 `罗小黑` / `比丢` 子目录内），不合规的条目自动拒绝入池。

## 2. 素材红线（与 docs/05 §5 一致）

| 项 | 规则 | 校验点 |
| --- | --- | --- |
| 来源 | 仅《罗小黑战记》官方图 | `channels` 段仅登记官方渠道；`review_log` 留痕 |
| 角色形象 | 必须官方原图，不得改画 / 不得再生成 | `redline.block_character_redraw = true` |
| UI 拆分组件 | 图标 / 边框 / 按钮 / 底板可用非角色重绘 | `redline.ui_component_exception` |
| 外链 | 数据与引擎层不得出现外链 | `verify_integration.py` 的 `redline.no-external-url` |
| 同人 / 第三方署名 | 排除 | 目录名与文件命名审查 |

## 6. 采集 SOP（后续执行）

1. **渠道选择**：优先 `ch_qq_emoji` / `ch_wechat_emoji`（官方表情包，成套、质量稳定）。
2. **授权前置**：端侧 App 采集需用户明确授权（登录态 + 导出），不得绕过。
3. **逐张人工审查**：每张图核对「官方渠道来源 / 是否角色原图 / 是否含第三方水印署名」三项，填写 `review_log`。
4. **登记入池**：写入 `pool.comfort`（或 `celebration`），路径统一为官方素材库绝对路径。
5. **回归校验**：`python data/scripts/validate_achievements.py` → `node data/scripts/smoke_test.js` → 集成包 `verify_integration.py`。
