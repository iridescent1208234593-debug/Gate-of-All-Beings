## 4. 三套接入方案（并行推进，按需选择）

### 方案 A · 零侵入（推荐先做，1 个短分支）

**思路**：不改任何 React 源码。站点入口 HTML 追加一行 `<script src="six-system-icons.js">`，
或在 `shared-ui/lxh-ui.js` 中合并六键（R1 已完成）。

**改动**：0 行组件代码，仅静态资源。
**效果**：`ELEMENTS`/`ABILITY_SYSTEMS` 相关位置可使用 `<LxhIcon name={...}/>` 渲染六系图标。
**分支**：`feat/sixsys-icon-mount`
**风险**：极低；失败仅需移除 script 标签。

### 方案 B · 组件化挂载（推荐主推，2 个短分支）

**思路**：新增独立组件，只做「插入」，不改战斗逻辑。

| 分支 | 新增 | 挂载点 |
|---|---|---|
| `feat/sixsys-icon-badge` | `SixSystemBadge.tsx`（图标+系名+色环） | `CardTile` 卡面 L32；`WorldGuide` 六系词表 L17 |
| `feat/sixsys-radar-panel` | `SixSystemRadar.tsx`（六维雷达 + 数值条） | `CardCollection` 卡牌详情；角色选择面板 |

**效果**：卡面出图标、角色详情出六系雷达；数值来源 `character_stats.json`。
**风险**：低；组件为纯展示，删除 import 即回滚。

### 方案 C · 数据驱动贯通（主线扩充，按批次）

**思路**：把 `decks.json` / `achievements.json` 通过构建产物注入站点，让
「卡组 = 488 角色主线阵容」「成就 = 收集图鉴」真正跑起来。

**分支**：`feat/sixsys-deck-bind`、`feat/sixsys-achievement`、`feat/sixsys-battle-settle`
**前置**：方案 A/B 已完成；`balanceOf` 后台快照结构对齐。
**风险**：中；涉及存档字段扩展，需灰度（先只读展示，再写入）。

### 方案对比

| 维度 | A 零侵入 | B 组件化 | C 数据驱动 |
|---|---|---|---|
| 改动面 | 静态资源 | 新增组件 + 少量 import | 数据/存档契约 |
| 周期 | 0.5 天 | 1–2 天 | 3–5 天 |
| 现网风险 | 极低 | 低 | 中 |
| 可视化程度 | 图标 | 图标 + 雷达 | 完整玩法 |
| 推荐顺序 | ① | ② | ③ |

## 8. 风险与回滚

| 风险 | 等级 | 处置 |
|---|---|---|
| 改动站点源码导致构建失败 | 中 | 每分支独立分支，回滚 = `git revert` 该 merge |

**回滚一句话**：删除分支 / revert merge / 移除 script 标签，三选一即可，均不损数据。
