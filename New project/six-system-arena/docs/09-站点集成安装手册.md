# 07 · 站点集成方案（zszm 端口）

> 目标：把六系演武的**数值产物 + 六系图标 + 结算组件 + 成就判定**接入 zszm 端口（众生之门）的
> 卡牌 / 经营 / 模拟三系统可视化，全程**复用站点既有机制**（`LxhIcon`、`window.LXHUI.ICONS`、
> `Card.school/element`、`Character.element/abilitySystems`、`CardTile` / `CardCollection` / 胜利失败结局区），
> **不改动 zszm 任何既有源码**——集成包只提供"可复制文件 + 可粘贴接线片段"。

---

## 1. 边界与红线

| 项 | 约定 |
| --- | --- |
| 产出位置 | 全部在 `E:\Projects\New project\six-system-arena\` 内；安装动作由站点侧显式执行 |
| 只读仓库 | `D:\Projects\zszm`、`E:\Projects\shared\shared-ui`、`E:\Projects\shared-types`、`E:\Projects\assets\罗小黑战记数据库` |
| 素材红线 | 仅《罗小黑战记》官方图；排除 `ai-art` / `ai-avatars` / `AI image` / 同人图；**本轮不联网采集** |
| 数据红线 | `worldview_luoxiaohei_v4.db` 只读；站点侧只消费 `data/generated/*.json` 产物，不回写 |
| 激活方式 | **零侵入**：加载 `six-system-icons.js` 即自动注册六键，**无需**执行 `patch_lxh_icons.py --apply` |

> 与 `docs/02` 的关系：`docs/02` 讲"图标如何进入共享 UI 体系"，本篇讲"图标与数值如何进入 zszm 三个玩法系统"。

```
├─ public\sixsys\                     ← 运行时资源（Vite public 根，URL 前缀 /sixsys/）
│  ├─ js\six-system-icons.js          ← 源：arena\ui\six-system-icons.js
│  ├─ js\SixSystemPanel.js            ← 源：arena\ui\SixSystemPanel.js
```

**为什么用 `public/`**：`vite.config.ts` 的 `server.fs.allow` 仅放行 `__dirname`、`../shared-types`、

`/sixsys/...` 在 dev 与 build 后均可直接访问，无需改配置。**不要**把六系资源放到 `../shared-ui` 之外的盘外目录。

## 3. 四步安装

### 3.1 复制运行时资源与数据

```powershell
$arena = 'E:\Projects\New project\six-system-arena'
$site  = 'D:\Projects\zszm\public\sixsys'
New-Item -ItemType Directory -Force -Path "$site\js","$site\css","$site\data","$site\official" | Out-Null
Copy-Item "$arena\ui\six-system-icons.js","$arena\ui\SixSystemPanel.js","$arena\ui\settlement.js","$arena\ui\battle-engine.js","$arena\ui\achievement-system.js" "$site\js\" -Force
```

> `integration/js`、`integration/data`，再整体复制到站点，避免版本漂移。

### 3.2 复制官方结算素材（默认 DRY-RUN）

```powershell

powershell -ExecutionPolicy Bypass -File "integration\verify\install_assets.ps1"
# 确认无误后真正复制
powershell -ExecutionPolicy Bypass -File "integration\verify\install_assets.ps1" -Apply
```

素材来源与落点见 `integration/assets.source.json` / `manifest.json` 的 `assets.whitelist`：
`罗小黑_全身_085.jpg`、`罗小黑_表情_087.jpg`、`罗小黑_表情_088.jpg`、`比丢.png`、`比丢.gif`。
脚本**只复制、不裁切、不联网、不改源**。

### 3.3 复制 TS 接入层并加一行引导

把 `integration/src/*` 复制到 `D:\Projects\zszm\src\game\sixsys\`，再新增引导文件：

```ts
// D:\Projects\zszm\src\game\sixsys\bootstrap.ts
import '../../../shared-ui/lxh-ui.js';          // 保证 window.LXHUI 先就位（幂等）
import '/sixsys/js/six-system-icons.js';        // 六系图标 → 自动注册 ICONS.jin/mu/shui/huo/tu/kongjian
import './sixsys-integration.css';

const icons = (window as unknown as { SixSystemIcons?: { registerIcons?: () => void } }).SixSystemIcons;
icons?.registerIcons?.();                        // 显式二次注册，彻底消除加载时序依赖

await import('/sixsys/js/settlement.js');        // 结算（胜利放小黑 + 比丢，失败放小黑安慰）
await import('/sixsys/js/battle-engine.js');     // 确定性对战内核
await import('/sixsys/js/achievement-system.js');// 收集类成就判定
```

在游戏入口顶部加**一行**：

```ts
// src/gate/GameShell.tsx（或 src/game/GameApp.tsx，二者取实际承载卡牌主游戏的入口）
import './sixsys/bootstrap';
```

> 为何不放在 `index.html`：`lxh-ui.js` 由 `LxhIcon.tsx` 以 ESM 方式 import，脚本时序不可控；
> 用 ESM 的**静态 import 顺序**（严格按书写顺序求值）才能保证 `LXHUI` 先于 `registerIcons()` 就位。

## 4. 三个系统的接入点

### 4.1 卡牌系统（`src/game/`）

现状（只读核对）：`core/types.ts` 的 `Card` 已预留 `school?: AbilitySystem` 与 `element?: Element`，
`Character` 亦有 `element` / `abilitySystems`；`GameApp.tsx` 的 `CardTile` 已展示
`c.school ? ABILITY_SYSTEMS[c.school] : c.type` 与 `ELEMENTS[c.element]`，只是**没有图标**。

**接线 2 —— 结局结算**（在原有结局 `<section className="encounter ending">` 之前并列插入）：

```tsx
import { SettlementStage, AchievementBanner } from './sixsys';

{['victory','defeat'].includes(run.phase) && (
  <>
    <SettlementStage
      result={run.phase === 'victory' ? 'win' : 'lose'}
      mode="story"
      myCharacterId={HEROES[run.hero].characterId}
      winnerElement={HEROES[run.hero].element}
      seed={run.seed}
      onRetry={() => send({ type: 'leave' })}
      onCollect={() => go('collection')}
    />
    <AchievementBanner delay={3000} />
  </>
)}
```

- 胜利：罗小黑登场 + 比丢登场（官方图），正向反馈文案；**不扣资源**。
- 失败：小黑官方表情图安慰，`penalty === false`，并给出「再试一次 / 回会馆休息」入口。
- 素材缺失时组件自动回落为六系图标 + 文案，不白屏、不引用任何非官方图。

**接线 3 —— 卡面六系图标**：

```tsx
// CardTile 的 card-top 内，系别文字后追加图标（element 取值即 ICONS 的六键）
<span>{c.school ? ABILITY_SYSTEMS[c.school] : c.type}{c.element ? ' · ' + ELEMENTS[c.element] : ''}
  {c.element && <LxhIcon name={c.element} />}
</span>
```

**卡牌图鉴增强（可选）**：在 `CardCollection.tsx` 的筛选栏增加"六系"选择器，
用 `loadSixSystemData().then(b => b.elementCounter())` 显示六系分布；
角色卡详情用 `<SixSystemPanel>` 渲染六系雷达。

### 4.2 经营系统（`ManagementPanel` → `/management/index.html`）

现状（只读核对）：`shared-types/models.d.ts` 的 `LingzhiSpace` **已预留 `element: Element`**，
`EcoExchange.space` 会随收获包投递到据点（`zszm:deliver-ecology`）。因此六系接入**不需要改协议**。

建议映射（`integration` 侧提供常量，站点按需取用）：

| 系 | key | 经营维度 | 加成方向建议 |
| --- | --- | --- | --- |
| 金 | `jin` | 营建 / 工具 | 建造效率、加工产出 |
| 木 | `mu` | 种植 / 生长 | 作物生长速度、药材产出 |
| 水 | `shui` | 灌溉 / 净化 | 水源恢复、损耗降低 |
| 火 | `huo` | 冶炼 / 加工 | 加工转化率、时段加速 |
| 土 | `tu` | 地力 / 仓储 | 仓储上限、土地肥力 |
| 空间 | `kongjian` | 物流 / 扩容 | 仓储扩容、跨区调运 |

落地方式（二选一，均为增量）：

1. **只读装饰**：据点内按 `packet.space.element` 显示六系图标与名称（`LxhIcon` + `eight-systems` 文案），零逻辑风险。
2. **加成读取**：经营侧维护一张「六系 → 加成系数」表，读取我方已解锁角色的 `element` 分布计算加成；
   收益公式与数值由经营侧自有模块承载，**本集成包不介入其结算**。

### 4.3 模拟系统（灵境生态 / 角色详情）

现状（只读核对）：`EcoIndividual` 已有 `element: Element` 与 `traits`；`shared-types/world.js`
已有 `ELEMENTS`、`CHARACTER_AFFINITIES`、`HERO_CHARACTER_IDS`。

- **生态观测**：对 `EcoIndividual` 按 `element` 聚合，渲染六系分布（复用 `SixSystemPanel` 的星图风格）。
- **角色详情页**：用 `<SixSystemPanel>` 展示 `character_stats.json` 的六维雷达 + hp/atk/def + 档位/稀有度：

```tsx
import { SixSystemPanel, loadSixSystemData } from './sixsys';

<SixSystemPanel characterId={1} />   // 自动取 488 角色产物中的 id=1（罗小黑）
```

- **数值一致性**：站点展示口径与产物字段一一对应（`hp/attack/defense/power/tier/rarity/element/systems`），
  不二次推导，避免与 arena 侧数值漂移。

## 5. 数据流

```
worldview_luoxiaohei_v4.db（只读）
   └─ generate_stats.py ─┐
                        ├─► data/generated/character_stats.json ─┐
   data/stat-model.json ─┘                                       │
   data/decks.json ◄── 卡组分配（488 套）                          ├─► copy → zszm/public/sixsys/data/
   data/achievements.json（15 条 + 竞争契约）                     │
                                                                 ▼
             zszm 站点：sixsys-data.ts（fetch /sixsys/data/*.json 或 window.SIXSYS_DATA 预注入）
                          ├─ 卡牌：CardTile 图标 · 结算 · 图鉴
                          ├─ 经营：灵质空间 element 装饰 / 加成
                          └─ 模拟：角色详情六系雷达 + 生态六系分布
```

**首屏优化（可选）**：若担心首屏抖动，可在 `index.html` 内联一段
`window.SIXSYS_DATA = { character_stats: {...} }` 预注入；`sixsys-data.ts` 优先读预注入值，缺失才 fetch。

**战斗日志写入点**（成就唯一输入，字段契约见 `data/achievements.json` 的 `battle_log_contract`）：
`battle-engine.js` 的 `toLogRecord(state)` 已按契约输出，站点只需把结果追加到自己的存档，
并在结算时调用 `SixSystemAchievement.judge(record)`。
