## 保存和数据流

1. 生态收获时，先把扣除后的库存、真实个体记录及待发送包写入生态存档。
2. 主入口验证 JSON，把生态卡资料和经营待入库队列一起写入 IndexedDB，成功后才向生态确认收到。
3. 进入据点经营后按序送入；经营检查容量、入账并保存，才发确认。重复投递不会重复加资源，容量不足保留整批等待处理。
4. 刷新或切换模块后可继续投递。消息同时检查同源和具体 iframe 来源。经营每 15 秒及退出页面时保存，生态退出时也保存。

v2 收获资源只进入据点库存；v1 老包保留原有日常会馆兼容行为。生态个体以世界与个体编号去重，最多保存 512 个；每批最多 12 个，待发送及待入库队列最多 100 批。卡牌效果由本地固定规则推导，不接受 JSON 注入的效果。六系为御灵、生灵、造物、空间、心灵、锁御，五行为金木水火土，维持两条独立分类轴。
