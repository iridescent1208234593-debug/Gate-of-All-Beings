# 卡牌数值后台与功能手册

2026-09-28 · 分支 `feat/card-balance-admin`。

## 使用

打开 `http://127.0.0.1:5182/#collection`，进入开场后：

1. 搜索卡牌或筛选同行者，点击卡牌打开数值管理。
2. 修改灵力消耗、18 种效果、作用目标、出牌条件和使用后消耗。效果为整数；0 关闭，表单旁有范围和结算说明。默认只展示卡牌已有的效果，可展开全部效果。
3. 上方预览随输入变化；点击“保存数值”才写入后台。取消修改不会保存。
4. “恢复默认并保存”只重置当前卡；每次写入都自动备份上一版。
5. 图鉴提供完整数值配置导出。页顶“功能说明”和导航问号内的“功能手册”解释每个玩法、效果与保存机制。

支持 98 张已有定义及浏览器已结缘的生态个体卡。数值调整不会自动解锁卡牌、改变同行者能力或把卡加入当前牌组。精进仍按原规则加成。

保存成功后，图鉴文字、费用和本页面的后续战斗结算使用同一份数值。已经发生的伤害和状态不重算；其他已打开页面点击“重新加载配置”或刷新。旧战斗动作回放须配套旧数值版本，配置备份应与重要的旅途存档一起保留。

## 后台与数据

Node/Express 后台由 Vite 插件在开发和本地预览时装配，不需要额外安装数据库或另外开端口。

```text
npm run dev

或构建后预览：
npm run build
npm run preview -- --host 127.0.0.1 --port 5182 --strictPort
```

本地配置：`server\app\src\cards\data\card-balance\config.json`。

历史备份：同目录 `backups\`。这些运行数据被 Git 忽略，重新构建不会覆盖。首次写入前没有配置文件时使用代码原始值。保存采用独占目录锁、版本冲突检查、先备份、临时文件原子替换；开发和预览共享此文件时也不会互相静默覆盖。

备份恢复：先停止本工程开发/预览服务，将当前 `config.json` 另存一份，然后把选定的后台备份或图鉴导出的完整 JSON 复制为 `config.json`，重启后重新加载配置。文件损坏时后台拒绝写入，保留原件。如进程被强制终止留下 `.write-lock` 空目录，确认没有本工程服务运行后才移除该锁目录。

游戏进度仍留在原浏览器存档中，不属于上述数值文件。备份不会改变据点、生态库存和旅途进度。

## 接口

| 路径 | 用途 |
| --- | --- |
| `GET /api/card-balance` | 读取版本、数值覆盖及是否可编辑。本机另返回写入令牌及完整备份数据。 |
| `PUT /api/card-balance/cards/:id` | 请求体 `{revision,value,individual?}`。value 为费用、效果、消耗、目标、条件；null 表示恢复该卡默认。生态个体需提供可校验来源或已存来源。 |

写入只接受本机回环连接、localhost/127.0.0.1 主机名、匹配来源及当前进程令牌。非本机访问只读；不提供公网管理员登录。服务重启后旧页面须重新加载配置以换取新令牌。未知字段、非法编号、超范围或小数输入、过期版本被拒绝。

纯静态托管没有此后台：需运行上述 Node 服务。读配置失败时前端明确提示并暂停历练操作，避免误套默认数值；其他功能仍可浏览。
